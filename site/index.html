What you get

Everything a small group needs to share photos with each other, and nothing built to keep you scrolling.

One shared feed

Photos in the order they were posted, with captions, likes, comments and @mentions.

Messages and notifications

Direct messages, a notification bell, and push notifications to phones.

Installs like an app

Members add it to their phone's Home Screen. No app store involved.

Profiles

Each member gets a profile with their posts, a posting streak and a likes podium.

Members stay in control

Blocking, a full data export, and account deletion for everyone.

Admin console

Invites, moderation, announcements, stats, and a private line between members and the admins.

Daily moment

Optional: a reminder at a time you pick, with a badge for photos posted on that exact minute.

Make it yours

Give your site its own name and accent colour.

Nothing leaves your machine

No outside services, no analytics, and the site sends no email.

Set it up

You need a computer that stays on — a spare PC, a mini PC or a home server — running Linux, macOS or Windows. That's all.

  1. Get the code

    Download the zip and unpack it, or clone the repository:

    git clone https://github.com/jthy10/nopostnow.git

  2. Run the launcher

    From inside that folder:

    Linux / macOS

    sh nopostnow.sh

    Windows

    .\nopostnow.cmd

    On Windows you can also just double-click nopostnow.cmd. If Node.js isn't installed, the launcher downloads an official copy into the folder for its own use. Nothing else is needed.

  3. Answer a few questions

    A control panel opens in your browser. The first time, it asks for:

    • the site's name and colour
    • where the photos are stored
    • the address and port
    • your admin account

    Then it starts the site. Open the address it shows — by default http://localhost:3000 — and sign in.

    From then on the panel shows your site's addresses and its live console, with Options for changing anything later and buttons for invite and password-reset links.

  4. Invite your friends

    Once the site has a public address (see below), create an invite link in the panel or under Admin → Members and send it to a friend. They open it, create an account, and add the site to their Home Screen.

No screen? Prefer the terminal?

On a machine you reach over SSH, the launcher uses a terminal wizard instead of the panel. You can ask for it with sh nopostnow.sh start. If you already have Node.js 22.18 or newer, npm ci followed by npm run panel does the same thing by hand.

Getting it online

Out of the box the site is reachable from your own network. To let friends in from anywhere — and to let phones install it and receive notifications — it needs a public https:// address.

  1. Get a domain

    About $10 a year from any registrar, or directly from Cloudflare. If you bought it elsewhere, add it to a free Cloudflare account.

  2. Create a Cloudflare Tunnel

    The tunnel is free. It connects out from your computer, so you don't open ports on your router and your home IP address is never published. Cloudflare's dashboard gives you one command to run on the computer hosting the site.

  3. Point your address at the site

    In the tunnel's settings, add a public hostname such as photos.example.com that sends traffic to localhost:3000. Then enter that address in the panel under Options → Getting online so invite links use it.

How it works

NoPostNow is a Next.js app with its own small server side. There are no outside services to sign up for or keep running.

What's inside

  • Data — one SQLite file, using the SQLite built into Node.js. Nothing to install or administer.
  • Photos — plain files in the data folder, served only to signed-in members.
  • Accounts — email and password, with optional authenticator-app two-factor sign-in.
  • Settings — one config.json, written by the control panel or the setup wizard.

How it protects your site

  • Passwords are stored as salted scrypt hashes; sessions live in an HttpOnly cookie.
  • Every read and write is authorized on the server. Anything not explicitly allowed is refused.
  • Photos have no public URL, and uploads are verified to be images by their content.
  • Admin changes need the password re-entered recently, plus an authenticator code when two-factor is on.
